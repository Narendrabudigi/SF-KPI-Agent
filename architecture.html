HR KPI Agentic AI Framework

Autonomous 24/7 SAP SuccessFactors & Datasphere Monitoring & Intelligent Root Cause Analysis

🛠️ Comprehensive Technology Stack

Backend & Orchestration

Python 3.12 FastAPI Uvicorn Threading python-dotenv

Where it's used: The core logic of the application. FastAPI/Uvicorn provide the web server and endpoints (/api/trigger, /manual). The Threading module manages the asynchronous orchestration, allowing continuous background monitoring without blocking API requests.

Deployment & Hosting

SAP BTP Cloud Foundry Linux Containers Python Buildpack

Where it's used: The application is hosted as an always-on container in SAP BTP. The manifest.yml and runtime.txt orchestrate the deployment, completely bypassing the short execution timeouts associated with serverless environments (like Vercel).

Data Extraction & Analytics

SAP Datasphere Databricks databricks-sql-connector Pandas

Where it's used: SAP Datasphere is polled via OData to identify HR KPI breaches from SAP SuccessFactors analytical models. Databricks is used as the heavy analytics engine running advanced ML Models (Isolation Forest, KMeans Clustering, PVM Decomposition). The RCA Coordinator uses the SQL Connector and Pandas to query and structure the final ML output tables.

Authentication & Security

OAuth2 Client Credentials Bearer Tokens Requests

Where it's used: Secure, machine-to-machine authentication. The Python requests library fetches an OAuth2 Bearer Token from SAP's XSUAA service, which is then passed securely to authenticate all SAP Datasphere OData API calls.

Artificial Intelligence

Google Gemini (1.5 Pro/Flash) Groq (Llama 3) OpenRouter

Where it's used: The Prescriptive LLM Agent uses these models to analyze the raw RCA data. It implements a resilient fallback chain (Primary: Gemini -> Secondary: Gemini Lite -> Tertiary: Groq -> Quaternary: OpenRouter) to guarantee HR insights are generated even if one provider goes down.

Notifications & UI

SMTP (email.mime) HTML/CSS MS Teams Webhooks Rich Console

Where it's used: The Notification Agent builds premium HTML emails and sends them via SMTP to specific HR stakeholders (TA Head, HRBP, CHRO, Payroll Manager, CFO). It also pushes JSON payloads to MS Teams. The terminal logs are beautifully styled using the Python Rich library.

🤖 Agent Ecosystem

👑 Master Orchestrator

The central nervous system. Runs 24/7 in a background thread, constantly polling the SAP Datasphere OData API via OAuth2 for HR KPI breaches sourced from SAP SuccessFactors. It identifies active breaches and dynamically routes them to the correct HR Domain Agent using parallel synchronous threads.

🏭 Domain Agents

(Recruitment, Onboarding/Offboarding, Employee Central, Employee Payment)
Specialized HR agents that receive breach alerts. They communicate with the Databricks Workspace via the REST API to trigger complex Machine Learning/RCA Notebooks specific to their HR domain.

⏳ RCA Coordinator (Scatter-Gather)

The synchronization engine. It uses a 1-Level Scatter-Gather pattern to monitor multiple parallel Databricks jobs simultaneously. It waits for all domain notebooks to finish, dynamically extracts the results (supporting arbitrary ML output schemas), and combines them into a single comprehensive Context Block.

🧠 Prescriptive LLM Agent

The intelligence layer. It takes the raw RCA data extracted from Databricks and formulates a rich context prompt. It queries the LLM fallback chain to generate human-readable insights, root cause summaries, and actionable next steps.

📬 Notification Agent

The messenger. Takes the final AI-generated HR insights and constructs beautifully formatted HTML emails. It dynamically routes these alerts to the correct stakeholders (TA Head, HRBP, CHRO, Payroll Manager, CFO) based on the HR KPI domain and severity level.

☁️ Databricks Dynamic Job Lifecycle

The system does not rely on static, pre-scheduled jobs in the Databricks UI. Instead, it creates jobs dynamically on-demand, ensuring highly efficient compute usage:

  1. The Trigger (API Call): When the Domain Agent detects a breach, it sends an HTTP POST to the Databricks Jobs API (/api/2.1/jobs/runs/submit) instructing it to execute a specific ML Notebook with dynamic parameters (like KPI Name, Year, Month).
  2. The Creation (Run ID): Databricks instantly creates a one-time job run for this specific breach and replies with a unique Run ID.
  3. The Execution (Compute Cluster): Databricks spins up a compute cluster, executes the Root Cause Analysis script, and writes the output to a Databricks SQL Table.
  4. The Monitoring & Fetch: The RCA Coordinator Agent continuously polls Databricks to monitor the Run ID status. Once the status hits SUCCESS, it uses the databricks-sql-connector to run a SQL SELECT query, pulling the finalized RCA data back into the Agentic framework for LLM analysis.

✨ Key Architectural Highlights

  • No Timeout Limits: By deploying as a continuous Python container on SAP BTP Cloud Foundry, the system completely avoids the restrictive 10-second serverless execution limits, allowing long-running Databricks jobs to complete naturally.
  • Secure Machine-to-Machine Auth: Completely migrated away from fragile browser-based SSO (Playwright) to robust, headless SAP OAuth2 Client Credentials flow.
  • Parallel Scatter-Gather Processing: The orchestrator utilizes a 1-level Scatter-Gather threading pattern to launch multiple Databricks jobs in parallel, significantly reducing the total RCA wait time.
  • Dynamic Schema Resilience: The SQL fetching layer is completely decoupled from the Databricks ML logic. The ML team can add as many advanced feature columns as they want to the final output, and the backend will seamlessly read and forward them to the Agentic LLM without breaking.
  • Resilient AI Fallback: If the primary Google Gemini model fails or hits a rate limit, the system automatically falls back to Groq Llama 3, and then OpenRouter, ensuring zero downtime for insights generation.
